## 이번 리팩토링 변경 파일

- `src/pipeline/phaseHandlers.ts` — 신규. 6개 페이즈 핸들러를 `registerPhaseHandler()`로 등록. 각 핸들러가 에이전트 호출 → 상태 저장 → `transition()`으로 다음 페이즈 전이
- `src/utils/roundStateMachine.ts` — 수정. `registerPhaseHandler()`, `runPhase()`, `isTerminalPhase()`, `clearPhaseHandlers()` 추가. 기존 `transition()`, setter, `canRetry()` 등은 변경 없음
- `src/types/index.ts` — 수정. `PipelineContext` (불변 컨텍스트), `PhaseHandler` (핸들러 시그니처) 타입 추가
- `src/index.ts` — 수정. 순차 실행 + while(true) 루프를 `while (!isTerminalPhase) { state = await runPhase(state, ctx) }` 디스패치 루프로 교체. 결과 출력을 `printResults()`/`printStats()` 헬퍼로 분리. fail report 출력을 핸들러에서 `printResults()`로 이동
- `src/pipeline/__tests__/phaseHandlers.test.ts` — 신규. 핸들러 통합 테스트 10건 (PASS/RETRY/FAIL 경로 + 전체 루프 2종)
- `src/utils/__tests__/roundStateMachine.test.ts` — 수정. `isTerminalPhase` 4건 + `registerPhaseHandler`/`runPhase` 3건 추가
- `CLAUDE.md` — 수정. 폴더 구조에 `src/pipeline/` 추가, 파일 분리 원칙에 핸들러 규칙 추가
- `README.md` — 수정. 상태 머신 설명을 디스패치 루프로 갱신, 프로젝트 구조 업데이트, 테스트 전략에 핸들러 통합 행 추가
- `docs/system-design.md` — 수정. 섹션 3에 실행 메커니즘 설명 추가, 섹션 16에 `PipelineContext` 및 핸들러 시그니처 설명 추가

## 리팩토링 동기

기존 `index.ts`의 `main()`은 에이전트를 순차 호출하고 `transition()`은 전환 유효성만 검증했다. 상태가 흐름을 제어하지 않고 코드 흐름이 상태를 업데이트하는 구조였다. 이를 상태 기반 디스패치 루프로 변경하여 진짜 상태 머신으로 만들었다.
